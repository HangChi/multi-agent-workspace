**Status**: Draft

## 背景与动机

002 已建立内置工具目录、Agent 级工具授权、工具调用审计和沙箱执行边界，但明确不包含外部工具服务器（MCP）接入与第三方工具市场。当前用户只能使用系统内置工具，无法在不修改核心系统的情况下接入团队已有能力或经过审核的第三方能力。

本特性提供一个受治理的外部工具扩展闭环：管理员登记并验证外部工具服务器，审核者将工具发布到市场，成员安装并授权工具给 Agent，运行时按授权调用，系统对凭证、版本、可用性、失败和审计进行统一管理。外部工具必须遵守 002 已建立的授权、资源归属、审计、成本和运行状态边界，不得形成一条绕过现有安全控制的执行通道。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 登记并验证外部工具服务器 (Priority: P1)

管理员将一个符合 MCP 约定的外部工具服务器加入工作台，填写名称、用途、连接信息和必要的认证信息。系统在正式开放前检查服务器是否可连接、能否发现工具、工具描述是否完整，并把验证结果展示给管理员。

**Why this priority**: 没有可靠的服务器登记和验证，市场中的工具无法建立信任，也无法保证用户看到的能力真实可用。

**Independent Test**: 使用一个可用服务器、一个不可达服务器和一个工具描述不完整的服务器分别登记，验证只有可用且通过校验的服务器可以进入待审核状态，并且每种失败都有可读原因。

**Acceptance Scenarios**:

1. **Given** 管理员填写完整且有效的服务器信息，**When** 提交登记，**Then** 系统验证连接并发现工具，展示服务器状态、工具数量和验证时间。
2. **Given** 服务器不可达或认证失败，**When** 管理员提交登记，**Then** 系统拒绝进入可发布状态，保留可读失败原因，且不泄露认证信息。
3. **Given** 服务器声明的工具缺少名称、说明或参数约束，**When** 系统验证工具目录，**Then** 该工具被标记为不可发布，并指出缺失项。
4. **Given** 服务器已登记，**When** 管理员再次发起验证，**Then** 系统更新当前验证结果，不修改既有运行的工具配置快照。

---

### User Story 2 - 审核并浏览第三方工具市场 (Priority: P1)

管理员或被授予审核权限的成员查看待审核服务器和工具，核对来源、权限范围、数据处理说明、版本和验证结果后批准或拒绝。普通成员可以在市场中搜索已发布工具，了解用途、所需权限、运行限制和维护状态。

**Why this priority**: 市场是外部能力进入工作台的治理入口；先审核再可见，才能避免未受信任的能力被 Agent 直接使用。

**Independent Test**: 创建一个待审核工具、一个已批准工具和一个被拒绝工具，分别用管理员、审核者和普通成员查看，验证各角色只能执行其被允许的操作，且市场只展示已发布工具。

**Acceptance Scenarios**:

1. **Given** 工具已完成验证但尚未审核，**When** 审核者查看待办，**Then** 可看到来源、声明能力、数据处理说明、版本和验证结果，并可批准或拒绝。
2. **Given** 工具被拒绝或暂停，**When** 普通成员搜索市场，**Then** 工具不可安装，且历史使用记录仍可查看其当时的名称和版本。
3. **Given** 工具已批准并发布，**When** 成员按关键词、类别或能力搜索，**Then** 可看到工具用途、所需权限、限制、版本和维护状态。
4. **Given** 审核者没有管理权限，**When** 其尝试修改全局工具状态或服务器凭证，**Then** 操作被拒绝并写入审计记录。

---

### User Story 3 - 安装外部工具并授权给 Agent (Priority: P1)

成员从市场安装已发布工具，并在编辑 Agent 时像选择内置工具一样授权一个或多个外部工具。成员能看到工具将代表该 Agent 访问的外部能力和所需凭证范围；未授权的工具不会出现在运行时可用工具中。

**Why this priority**: 市场只有在能安全地落到 Agent 的授权配置上时才产生实际价值；授权一致性也是 002 的核心安全承诺。

**Independent Test**: 安装两个工具并分别授权给两个 Agent，使用同一个模型请求调用全部工具，验证每个 Agent 只能成功调用自己的授权集合，空授权 Agent 不会暴露外部工具。

**Acceptance Scenarios**:

1. **Given** 成员已安装一个已发布工具，**When** 编辑 Agent 并保存授权，**Then** Agent 配置显示该工具及其版本和权限说明。
2. **Given** Agent 未授权外部工具，**When** 运行中模型请求该工具，**Then** 调用被拒绝、模型收到可读原因，并留下越权记录。
3. **Given** 外部工具被暂停或撤销，**When** 成员打开已授权 Agent，**Then** 系统明确标示该工具不可用，并阻止新的运行调用；历史配置快照保持不变。
4. **Given** 工具发布新版本且成员未批准升级，**When** Agent 运行，**Then** 按该 Agent 已锁定的版本执行，不静默改变行为。

---

### User Story 4 - 在运行中调用外部工具 (Priority: P1)

Agent 在推理过程中调用已授权的外部工具。用户能在运行详情中看到调用的工具、版本、耗时、成功或失败状态和可读结果；外部工具的结果回到同一条运行链路中，供 Agent 继续完成任务。

**Why this priority**: 这是外部工具接入对最终用户的核心价值，也是验证授权、错误处理和实时可见性是否闭环的关键路径。

**Independent Test**: 使用一个返回结构化结果的外部工具、一个超时工具和一个返回错误的工具执行请求，验证成功结果可继续推理，失败结果被明确区分且不会伪装成成功。

**Acceptance Scenarios**:

1. **Given** Agent 已授权且工具服务器健康，**When** 模型调用工具并提供符合约束的参数，**Then** 系统执行调用，将结果回传给 Agent，并在运行详情记录调用事实。
2. **Given** 模型提供不符合工具参数约束的输入，**When** 系统准备调用，**Then** 调用不发送到外部服务器，模型收到可修正的参数错误。
3. **Given** 外部服务器超时、不可用或返回错误，**When** 调用结束，**Then** 步骤标记为失败并区分失败类别，Agent 不会收到伪造的成功结果。
4. **Given** 用户取消运行或运行达到总时长预算，**When** 外部调用仍在进行，**Then** 调用停止或不再接受结果，运行按既有状态机进入取消或超时状态。
5. **Given** 外部工具返回超大、不可读或包含敏感字段的结果，**When** 系统回填运行，**Then** 结果按限制安全截断或降级展示，凭证和敏感值不出现在用户界面或日志中。

---

### User Story 5 - 管理版本、凭证与使用审计 (Priority: P2)

管理员需要知道哪些外部能力正在被使用、由谁维护、使用了哪一版和哪项凭证，并能在凭证泄露、工具失效或版本不兼容时快速暂停、轮换或撤销。审计人员可以按服务器、工具、Agent、用户和运行追溯完整的变更与调用记录。

**Why this priority**: 外部系统引入新的信任边界和凭证风险。没有可回溯的生命周期管理，系统无法安全地长期运营市场能力。

**Independent Test**: 完成一次凭证轮换、一次版本升级、一次工具暂停和一次调用审计查询，验证新运行使用最新允许配置，旧运行保留原快照，所有变更均可追溯。

**Acceptance Scenarios**:

1. **Given** 管理员轮换服务器凭证，**When** 新运行开始，**Then** 只使用新凭证，旧凭证不再可用于新的调用且不会被展示。
2. **Given** 工具存在新版本，**When** 管理员发布升级，**Then** 可查看版本差异和兼容性结果，并选择保持旧版或让指定 Agent 升级。
3. **Given** 管理员暂停一个服务器，**When** 新运行或排队运行尝试调用其工具，**Then** 调用被阻止并给出可读原因，已完成运行的历史记录不被修改。
4. **Given** 审计人员按条件查询，**When** 选择某次外部调用，**Then** 可看到操作者、Agent、运行、工具版本、结果、耗时和策略结果，但看不到凭证原文。

---

### Edge Cases

- 服务器在登记后改变工具名称、参数约束或声明能力：重新验证必须识别差异，未审核的变化不能静默影响已授权 Agent。
- 同一服务器重复登记或不同服务器声明相同工具标识：系统必须避免市场中的工具无法区分，并明确来源和版本。
- 外部服务器返回部分工具或重复工具：登记结果应保留可用项并明确标记不可用项，不得把不完整目录当作完整成功。
- 服务器通过验证后在调用前失联：运行应快速失败并说明是外部服务不可用，不应无限重试或伪造结果。
- 外部服务器响应缓慢、持续推送或返回超过大小限制的内容：调用必须受单次限制约束，不影响其他运行。
- 外部服务器要求凭证但当前 Agent 没有可用授权：调用必须在发送前拒绝，不得尝试使用其他用户或服务器的凭证。
- 成员被移出项目或失去工具使用权限：其新运行不得继续使用已安装工具，历史记录仍按归属规则可追溯。
- 工具被撤销时存在正在执行的调用：新调用立即阻止，正在执行的调用按取消策略结束，并保留实际结果状态。
- 市场查询结果包含已下线工具的历史引用：历史运行显示当时的工具名称和版本，但不提供重新安装入口。
- 外部工具返回恶意提示或要求越权操作：结果只能作为不可信工具输出处理，不得改变 Agent 授权、系统权限或审计策略。

## Requirements *(mandatory)*

### Functional Requirements

**服务器登记与发现**

- **FR-001**: 系统 MUST 允许有权限的管理员登记符合 MCP 约定的外部工具服务器，并记录名称、用途、来源、连接信息、维护者、状态和创建者。
- **FR-002**: 系统 MUST 在服务器进入可审核状态前验证其可连接性、认证结果和工具目录完整性，并展示每项验证的时间与结果。
- **FR-003**: 系统 MUST 从已验证的服务器发现工具名称、说明、参数约束、能力类别、版本和所需权限，并保留来源服务器关联。
- **FR-004**: 服务器或工具验证失败时，系统 MUST 阻止其进入可安装或可调用状态，并返回不包含凭证原文或内部敏感信息的可读原因。
- **FR-005**: 重新验证发现工具目录变化时，系统 MUST 标记变化并要求重新审核；变化 MUST NOT 静默修改既有 Agent 的版本或历史运行快照。

**市场治理**

- **FR-006**: 系统 MUST 为外部服务器和工具提供明确的生命周期状态，至少覆盖待审核、已发布、已暂停、已拒绝和已撤销。
- **FR-007**: 只有完成必要审核且处于已发布状态的工具 MUST 出现在成员可浏览和安装的市场中。
- **FR-008**: 市场 MUST 支持按关键词、类别、能力、维护状态和版本筛选，并展示工具用途、来源、权限范围、限制、验证时间和维护状态。
- **FR-009**: 有权限的审核者 MUST 能批准、拒绝、暂停和撤销服务器或工具，并必须填写可追溯的变更原因。
- **FR-010**: 系统 MUST 保留工具发布版本和兼容性信息，允许管理者控制升级范围；版本升级 MUST NOT 静默改变已锁定 Agent 的运行行为。

**安装与授权**

- **FR-011**: 成员 MUST 能安装已发布工具并将其授权给自己有权编辑的 Agent；安装和授权 MUST 遵循现有资源归属和角色校验。
- **FR-012**: Agent 的外部工具可用集合 MUST 等于已发布、已安装、未暂停或撤销且明确授权的工具集合；未满足任一条件的工具 MUST NOT 暴露给模型或成功调用。
- **FR-013**: Agent 未授权外部工具或请求调用未授权工具时，系统 MUST 在发送到外部服务器前拒绝调用，向模型返回可读原因，并记录越权事件。
- **FR-014**: Agent 的运行配置 MUST 保存实际使用的工具版本和权限快照，使历史运行不因后续市场变化而被追溯修改。

**调用与运行**

- **FR-015**: 系统 MUST 通过统一的运行链路调用 Agent 已授权的外部工具，并将成功结果回传给 Agent 继续推理。
- **FR-016**: 系统 MUST 在调用前校验参数约束、工具状态、凭证授权和调用配额；校验失败时不得向外部服务器发送请求。
- **FR-017**: 外部工具调用 MUST 具有单次超时、结果大小、并发和重试边界；达到边界时 MUST 释放调用资源并返回明确失败类别。
- **FR-018**: 外部服务器不可用、认证失败、超时、参数错误、策略拒绝和工具自身错误 MUST 被区分记录，不得以成功结果回填给模型。
- **FR-019**: 外部调用 MUST 复用既有运行状态机、实时日志和运行详情；用户取消或运行超时后，不得把迟到的外部结果写入已终止运行。
- **FR-020**: 外部工具返回内容 MUST 被视为不可信输入，系统 MUST 限制其大小和展示范围，并 MUST NOT 允许其修改授权、凭证、审计或系统管理状态。

**凭证、权限与安全**

- **FR-021**: 外部服务器认证信息 MUST 以受保护形式保存，凭证原文 MUST NOT 出现在日志、市场详情、运行输出、审计展示或模型上下文中。
- **FR-022**: 系统 MUST 支持按服务器或工具范围管理凭证授权；Agent 只能使用被明确授予其所属用户和项目范围的凭证。
- **FR-023**: 凭证轮换、撤销和服务器暂停 MUST 对新调用立即生效；正在进行的调用按既有取消策略结束，并记录最终状态。
- **FR-024**: 外部工具调用 MUST 遵守现有成本上限、用户配额、并发限制和审计要求，不得通过外部服务器绕过这些控制。
- **FR-025**: 所有服务器登记、验证、审核、安装、授权、版本变更、凭证变更、暂停、撤销和调用 MUST 写入可查询审计记录，至少包含操作者、时间、服务器、工具、版本、Agent、运行和结果。
- **FR-026**: 外部服务器只能获得完成已授权工具调用所需的输入和凭证范围，系统 MUST 不得向其发送无关的用户数据、其他运行数据或系统内部凭证。

### Scope Boundaries *(explicit exclusions)*

- **不含** 002 未完成项的补做或重构；本特性只消费 002 已定义的工具授权、运行状态、审计和资源控制边界。
- **不含** 面向公众的开放注册、支付、分成、评分激励或商业化第三方应用商店；v1 的市场是受工作台治理的工具目录。
- **不含** 在平台内执行任意第三方代码、上传自定义镜像或绕过沙箱的运行方式。
- **不含** 自动批准未验证来源的服务器或工具；所有进入成员市场的能力必须经过明确治理状态。
- **不含** 让外部工具修改 Agent 配置、系统权限、凭证、审计记录或其他用户资源。
- **不含** 跨工作台租户共享私有服务器或凭证；跨租户共享能力需要独立的权限与合规设计。

### Key Entities *(include if feature involves data)*

- **外部工具服务器（ExternalToolServer）**: 一个由工作台登记的 MCP 服务器，含来源、连接信息、认证要求、维护者、生命周期状态和最近验证结果。
- **外部工具（ExternalTool）**: 服务器提供的一个能力单元，含名称、说明、参数约束、权限范围、类别、版本、来源服务器和发布状态。
- **市场发布（MarketplaceListing）**: 将已审核的外部工具提供给成员浏览和安装的记录，含发布版本、兼容性说明、维护信息、限制和审核轨迹。
- **工具安装（ToolInstallation）**: 项目或用户对市场工具的安装关系，含安装者、允许版本范围、状态和安装时间。
- **外部工具授权（ExternalToolGrant）**: Agent 对已安装工具的明确授权，含 Agent、工具版本、权限范围、凭证引用和配置快照。
- **服务器凭证（ServerCredential）**: 外部服务器调用所需的受保护认证材料，含归属范围、用途、轮换时间、状态和最后使用时间，不含可展示的凭证原文。
- **工具调用记录（ExternalToolInvocation）**: 一次外部工具调用的可审计事实，含用户、Agent、运行、服务器、工具版本、参数摘要、结果类别、耗时和策略结果。
- **验证记录（ServerValidation）**: 一次服务器连接、认证和工具目录检查的结果，含检查时间、阶段、状态、错误摘要和发现的版本信息。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 有权限的管理员从填写信息到看到验证结果的成功路径，在已有有效服务器信息的情况下，95% 的操作可在 3 分钟内完成。
- **SC-002**: 100% 出现在成员市场中的工具都能完成目录发现和健康验证；验证失败或状态不可用的工具不得被成功安装。
- **SC-003**: 在包含空授权、单工具授权、多工具授权和已撤销工具的测试中，Agent 实际可调用集合与授权快照 100% 一致，未授权调用静默成功次数为 0。
- **SC-004**: 正常外部工具调用中，95% 的调用能在外部服务自身响应后 2 秒内向用户显示成功或明确失败状态；超时调用 100% 在单次限制内结束。
- **SC-005**: 工具暂停、撤销或凭证撤销后，100% 的新调用在发送到外部服务器前被阻止；已终止运行不接收迟到结果。
- **SC-006**: 服务器登记、审核、安装、授权、凭证变更和调用事件的审计覆盖率达到 100%，且抽查记录不包含凭证原文。
- **SC-007**: 版本升级验证中，100% 未同意升级的 Agent 继续使用其锁定版本，历史运行的工具和版本展示不被后续变更改写。
- **SC-008**: 在 20 个并发外部调用和 20 个并发失败调用的验证中，既有运行状态机和核心用户操作无失败，外部调用失败均能归类为可读原因。
- **SC-009**: 试用用户完成“搜索市场—安装工具—授权 Agent—完成一次调用”的成功率达到 90% 以上，且无需接触服务器凭证原文。

## Assumptions

- 003 以 002 已落地或约定的 Agent 工具白名单、运行状态机、实时日志、成本配额、审计日志和资源归属校验为基础，不重新定义这些机制。
- MCP 是外部工具服务器与工作台之间的互操作约定；v1 先支持项目选择的一种稳定通信形态，其他通信形态按兼容性和安全评估后扩展。
- v1 市场面向工作台内的团队成员，服务器来源由管理员或受信任维护者管理，不包含公开投稿和自动上架。
- 外部服务器的网络可达性、服务质量和业务正确性由其维护者负责；工作台负责连接验证、边界控制、失败呈现和审计。
- 外部工具调用默认继承 Agent、用户和运行的成本、时长、并发与数据范围限制；若外部工具要求更高权限，必须显式配置并通过审核。
- 服务器凭证由管理员或被授权成员配置和轮换；成员可以使用被授予的能力，但不需要也不应能读取凭证原文。
- 市场中的已发布工具必须提供可供审核的用途、数据处理说明、维护者和版本信息；缺失这些信息的工具不进入成员市场。

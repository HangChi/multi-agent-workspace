# Feature Specification: 项目成员角色（019）

**Feature Branch**: `feat/019-project-member-roles`（已合并 master）

**Created**: 2026-11-21

**Status**: Implemented

**Input**: 用户 2026-11-21「把 README 已知限制里 A3–A8 逐个完成」。
A3 = 项目成员角色（role 列），010 当时明确「不设」。

## 问题陈述

010 的两层模型是「owner 全权 + 成员读写」——**成员身份即角色**。这在所有成员
权限完全一致时成立，但挡不住一类真实诉求：**只想看，不想改**。

出现过的具体场景：
- 跨团队知情：隔壁组要知道「这批需求有没有排上」，但不该改我们的需求；
- 外部协作方/甲方：能看到进度，不能改内容、更不能推去执行；
- 审计/复盘：只读历史与依赖关系。

二元模型下只能用「不加成员」来近似，代价是**连可见性一起丢掉**——于是有人
截图发微信，回到系统外。

## 设计决策

**加 `role` 列，只两个值**：`editor`（默认，= 010 的既有行为）/ `viewer`（只读）。
owner 仍是 `projects.owner_id`，不在成员表（R-01 不变）。

不做的事（明确排除）：
- 自定义角色 / 权限矩阵（A4 的「分派权限矩阵」是另一个维度：谁能把需求派给谁）；
- 字段级只读（例如「能看需求但不能看成本」）——没有需求，且会让判定点爆炸；
- 角色继承、角色组。

## 权限矩阵（本次唯一的真相）

| 动作 | owner | editor | viewer | 非参与者 |
|---|---|---|---|---|
| 读项目 / 读成员列表 | ✅ | ✅ | ✅ | 404 |
| 读项目内需求 | ✅ | ✅ | ✅ | 404 |
| 改需求（PATCH） | ✅ | ✅ | **403** | 404 |
| 分配执行（drag → Agent/组） | ✅ | ✅ | **403** | 404 |
| 转交责任（drag → 员工） | ✅ | ❌（007 谓词） | ❌ | 404 |
| 加/移除成员、改项目、归档、删除、移交 | ✅ | 403 | 403 | 404 |
| 建需求到该项目 | ✅ | ❌（008：仅 owner） | ❌ | 404 |

两条容易搞错的：
1. **转交责任对 editor 也是 403**：那是 007 的 owner-or-assignee 谓词，成员本就
   不能转交。019 不改它（改了就动 007 契约）。「分工协作」应走需求的项目归属
   + 分配执行，而不是替别人转交责任。
2. **建需求到该项目仍是 owner 专属**（008 的 `load_active_owned_project`）。
   editor 想加活，走「建在我的名下 + 改项目归属」——归属变更也仅创建者或项目
   owner（008 R-05）。这是既有契约，019 不碰。

## 需求（Functional）

- **FR-001** `project_members` 增加 `role`（varchar(20)，`editor`/`viewer`，
  CHECK 约束，`server_default='editor'`）。迁移 0019 零回填。
- **FR-002** `POST /projects/{id}/members` 接受 `role`（默认 `editor`），
  非法值 422（schema Literal）；service 直接调用非法值 400（防御第二道）。
- **FR-003** `GET /projects/{id}/members` 每项返回 `role`；**owner 行的
  role 是 `owner`**（不在成员表里，合成时标注）。
- **FR-004** 写操作（`PATCH /requests/{id}`、`POST /requests/{id}/assign`）
  对「仅靠成员身份进来」的调用者要求 `can_write_in_project`；否则 **403**
  且消息说清「你在该项目是只读成员」。
- **FR-005** owner 与 assignee 不受 role 限制（他们不是靠成员身份进来的）。
- **FR-006** 只读成员的读能力不下调：项目详情、成员列表、项目内需求、按项目
  筛选的需求列表全部照旧。
- **FR-007** 前端成员区：非 owner 行显示「只读 / 可编辑」徽章；owner 添加成员
  时可选角色；只读成员在自己视角看到一句说明。
- **FR-008** 019 之前的既有成员行迁移后行为不变（默认 editor）。

## 错误码

| 条件 | 状态 | 说明 |
|---|---|---|
| viewer 改需求 / 分配 | 403 `FORBIDDEN` | 他知道存在，只是没权限（016 分工） |
| 非参与者 | 404 | 不暴露存在性（016） |
| 非法 role（HTTP） | 422 `VALIDATION_ERROR` | Literal |
| 非法 role（service） | 400 `INVALID_INPUT` | 防御第二道 |

## 成功标准

- SC-001 viewer 能读到项目、需求、成员列表（读能力不被削减）。
- SC-002 viewer 改需求/分配得 403，且**状态没变**（不是先写后拒）。
- SC-003 editor 的既有行为不变（010 的回归测试全绿）。
- SC-004 既有成员行迁移后 `role='editor'`，无需回填。

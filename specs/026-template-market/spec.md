# Feature Specification: 模板市场（026，023 的范围外补做）

**Status**: Implemented（2026-11-21）

## 问题陈述

023 做了团队共享（`visibility=team`），但「共享出来的模板在哪看、怎么用」没有闭环：
别人的 team 模板只出现在列表的第三分组里，没有作者信息，想用只能「从模板创建 Agent」
（这会直接产出一个 Agent，而他其实只想改两个字段）。

「模板市场」的真实诉求只有三条：**能看到别人的、知道是谁的、拿来改成自己的**。
审核、评分、评论、举报是内容平台的工程量，内部规模用不上——这一点在 023 的
research 里已经论证过，026 延续同样的边界。

## 设计

1. **浏览**：`GET /agent-templates?scope=team`（023 已有）+ 每项返回 `owner_email`。
2. **知道是谁的**：卡片上显示「来自 xxx@…」，市场里没有署名的模板没人敢用。
3. **拿来改**：`POST /agent-templates/{id}/duplicate` → 复制成**自己的私有副本**。

复制（duplicate）与导入（import）的差别：

| | duplicate | import |
|---|---|---|
| 来源 | 服务端已有的模板 | 外部 JSON |
| 重名 | **自动加后缀**（`（副本）`/`（副本 2）`） | 409 |
| 结果可见性 | private | private |

为什么重名策略相反：复制是显式「我要再来一份」，拒绝它没有任何好处；导入是
「这份我是不是已经有了」，需要用户自己判断。

## 需求

- **FR-001** `POST /agent-templates/{id}/duplicate`：复制可见模板（自己的/内置/别人的 team）。
- **FR-002** 复制自己的模板 → 409（不需要复制）。
- **FR-003** 复制别人的 private → 404（不可见即不存在）。
- **FR-004** 副本恒为 private、名字自动加「（副本）」并在冲突时加序号。
- **FR-005** `GET /agent-templates` 每项返回 `owner_email`（一次 IN 查询，不逐行）。
- **FR-006** 前端：团队共享分组卡片加「复制到我的」，并显示「来自 xxx」。
- **FR-007** 配置字段逐字复制（含 tools / egress_mode / 成本上限）。

## 成功标准

- SC-001 复制 team 模板 → 201、private、名字带「（副本）」、配置一致。
- SC-002 复制自己的 → 409；复制别人的 private → 404。
- SC-003 团队列表返回 owner_email。

## 实测（2026-11-21）

- 后端新增 4 例（复制成功 / 复制自己 409 / 私有 404 / 作者字段），
  全量 **2119 passed**，覆盖率 **94.14%**；
- 前端 155 passed（团队卡片断言加了「复制到我的」存在且仅 1 个）；
- 真实栈 `deploy/verify/s21_template_market.py` **3/3**（复制 / 署名 / 两条边界）。

## 范围外

- 审核 / 评分 / 评论 / 举报（内容平台工程量，内部规模不需要）；
- 模板使用统计（「被复制了几次」需要事件表，等有排序需求再说）；
- 按部门筛选模板（模板没有部门归属，加它要先想清「模板属于部门还是属于人」）。

# Feature Specification: 沙箱代码执行与工具授权（Sandboxed Tools）

**Feature Branch**: `feat/sandboxed-tools`

**Created**: 2026-11-14

**Status**: Draft

**Input**: User description: "Phase 2 引擎强化之一：Agent 能在隔离沙箱中安全执行脚本（代码/命令）并回收产出文件；Agent 勾选的工具集必须真正生效，工具目录与实际能力一致。"

## 背景与动机（Upstream）

- 宪法《合规与安全边界》要求「用户提交的任意脚本 MUST 只能运行在隔离沙箱中」，当前系统尚无任何脚本执行能力；Phase 2 的验收口径「任意类型任务（写文章、跑脚本、调外部 API）均可执行」因此无法达成。
- 当前 Agent 的「工具白名单」是形式化的：可勾选的工具名与实际具备执行能力的工具不是同一组，且执行时并不按勾选注入。**用户以为限制了工具，实际没有**；界面上「未选择工具时，Agent 只能用模型自身知识作答」的承诺也不成立。
- 本特性把「能执行代码」与「工具授权真的生效」一并收口，因为二者是同一件事的两面：没有真实工具目录，授权无从谈起；没有授权，新工具一上线就等于对所有 Agent 默认开放。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 在隔离环境中执行脚本 (Priority: P1)

用户把一个需要计算、数据处理或调用本地工具的需求交给 Agent。Agent 在推理过程中编写一段 Python 或 shell 脚本并请求执行。系统在一个独立、用完即弃的隔离环境中运行它，把标准输出、标准错误和退出码回传给 Agent 继续推理；运行详情里用户能看到「执行了什么代码、输出是什么、花了多久」。

**Why this priority**: 这是「任意类型任务」缺口的最后一块，也是宪法明文要求却完全未兑现的能力。没有它，P2 无法验收，Agent 永远只能"动嘴"。

**Independent Test**: 创建一个只勾选代码执行工具的 Agent，提交「计算 1 到 100 的平方和并打印」，验证运行详情出现执行步骤、脚本内容、正确输出与耗时，且需求最终完成。

**Acceptance Scenarios**:

1. **Given** Agent 已勾选代码执行工具，**When** 需求需要一段 Python 脚本得出结果，**Then** 系统执行脚本并把标准输出回传给 Agent，Agent 继续推理
2. **Given** 脚本执行成功，**When** 用户打开运行详情，**Then** 可看到该次执行的代码、输出、退出码与耗时
3. **Given** 脚本执行返回非零退出码，**When** 执行结束，**Then** 该步骤被标记失败并携带可读错误，Agent 能据此修正而不是拿到"假成功"
4. **Given** 脚本执行中用户取消运行，**When** 取消生效，**Then** 脚本立即被终止、资源释放，运行进入已取消

---

### User Story 2 - 勾选的工具才真的可用 (Priority: P1)

用户编辑 Agent 时勾选「联网搜索」和「执行代码」，不勾「抓取网页」。运行该 Agent 时，模型只能看到并使用被勾选的两个工具；如果模型硬要调用未勾选的工具，系统拒绝调用、把拒绝原因告诉模型，并留下一条可查的记录。可选工具列表里出现的每一个工具都真的能用，不会再出现"选了等于没选"。

**Why this priority**: 这是当前系统的一处正确性缺陷（而非缺失功能），直接影响成本可控与安全边界；且 US1 新增的工具必须靠它才能真正按 Agent 粒度开放。

**Independent Test**: 建两个 Agent，一个只勾「计算」、一个只勾「联网搜索」，用同一个伪造成"想调所有工具"的模型驱动，验证前者只能成功调用计算、后者只能成功调用搜索，越界调用均被拒并留痕。

**Acceptance Scenarios**:

1. **Given** Agent 勾选了工具 A 未勾选工具 B，**When** 模型尝试调用 B，**Then** 调用被拒绝，模型收到可读拒绝原因，系统记录一条拒绝记录
2. **Given** Agent 未勾选任何工具，**When** 运行该 Agent，**Then** 模型侧无任何可用工具，且不会出现任何工具调用成功
3. **Given** 用户在编辑页看到可选工具列表，**When** 逐个勾选并运行，**Then** 每个列出的工具都真实可用（无"有名无实"的选项）
4. **Given** 某个工具从目录中下线，**When** 用户查看历史运行，**Then** 历史配置快照仍显示当时的工具集，不被追溯篡改

---

### User Story 3 - 脚本产出文件成为可下载制品 (Priority: P2)

Agent 跑脚本生成了图表、表格或报告文件。用户不需要去服务器上找，直接在运行详情里下载；下载到的文件与脚本当时写出的内容完全一致。

**Why this priority**: 没有产出回收，"跑脚本"只能产出文字，无法交付真实工作物；但它是 US1 的价值延伸，可在 US1 之后独立补齐。

**Independent Test**: 提交一个生成 CSV 并写入若干行的需求，验证运行详情出现该文件、可下载、内容行数与内容与脚本逻辑一致。

**Acceptance Scenarios**:

1. **Given** 脚本在工作目录写出一个 CSV，**When** 执行成功结束，**Then** 该文件作为制品出现在运行详情并可下载
2. **Given** 制品已生成，**When** 另一名用户尝试下载，**Then** 下载被拒绝（归属校验）
3. **Given** 脚本试图产出超过上限的文件，**When** 执行结束，**Then** 超限部分被截断且系统明确提示已截断

---

### User Story 4 - 执行可观测、可追责、受配额约束 (Priority: P2)

管理员想知道"谁在用沙箱、跑了多久、失败在哪"。每次脚本执行都留下结构化记录：谁、哪个 Agent、哪个运行、什么语言、耗时、资源峰值、退出码、失败分类；并计入个人用量，超出并发/时长配额时排队或拒绝并明确提示，而不是把机器拖死。

**Why this priority**: 上百并发的目标是宪法与架构前提；没有计量与限流，一个死循环脚本就能拖垮全站。它依赖 US1 存在，但可以独立验收。

**Independent Test**: 连续触发多次脚本执行（含一次死循环、一次内存暴涨），验证记录字段齐全、失败分类正确、超配额时被拒绝且给出提示、其他接口不受影响。

**Acceptance Scenarios**:

1. **Given** 一次脚本执行结束，**When** 管理员查询执行记录，**Then** 可看到耗时、资源峰值、退出码与失败分类
2. **Given** 用户同时发起的脚本执行超过并发上限，**When** 新的执行请求到达，**Then** 请求进入排队或被拒绝并给出可读提示，系统其他功能不受影响
3. **Given** 脚本因内存超限被终止，**When** 用户查看运行详情，**Then** 失败原因显示为"资源超限"而非笼统的"未知错误"

---

### User Story 5 - 出网受控 (Priority: P3)

安全负责人要求沙箱默认不能访问外网（防止数据外泄与被当作跳板）。确有需要时，管理员按域名白名单放行，白名单之外仍然拒绝，且每次拒绝都留痕。

**Why this priority**: 是安全纵深，但默认全禁即可满足上线底线；白名单是运营侧的精细化能力，可后置。

**Independent Test**: 默认配置下让脚本访问任意外网地址，验证失败且原因为"网络被禁止"；加入某域名到白名单后仅该域名可访问，其他仍失败。

**Acceptance Scenarios**:

1. **Given** 沙箱默认策略，**When** 脚本尝试访问外网，**Then** 访问失败并返回可读原因
2. **Given** 管理员已放行某域名，**When** 脚本访问该域名，**Then** 访问成功；访问未放行域名仍失败且留痕

---

### Edge Cases

- 脚本死循环或长时间阻塞：达到时长上限被强制终止，运行不无限挂起。
- 内存耗尽（申请远大于配额的数组）：只有该次执行被杀，执行引擎与其他运行不受影响。
- 脚本尝试读取宿主文件、环境变量中的密钥、其他运行的工作目录：一律不可见，读操作失败。
- 脚本尝试 fork 大量子进程或残留后台进程：执行结束必须无残留，进程树被整体回收。
- 脚本写出巨量标准输出（如死循环打印）：输出被截断保留尾部，并标注原始长度，避免撑爆存储与推送通道。
- 脚本写出大量文件或单个超大文件：按上限截断并提示，不因制品收集失败而让整个运行失败。
- 脚本写出二进制文件或不可读编码的输出：不导致整次执行崩溃，输出以可读形式降级展示。
- 多个执行同时产出同名文件：制品命名不得互相覆盖，均可在详情中区分下载。
- 隔离环境启动失败（镜像缺失、执行节点不可用）：快速失败并给出可读原因，禁止无限重试，禁止把失败伪装成成功输出。
- 网络被禁止时脚本抛出的连接错误：错误信息应能帮助模型判断"是策略禁止"而非"目标站点故障"。
- 模型连续多次调用未授权工具：每次都被拒绝，不因重复而放宽；超过阈值后该步骤应终止并给出提示。
- 历史运行引用了已下线工具：查看历史时仍显示当时配置，不报错。

## Requirements *(mandatory)*

### Functional Requirements

**工具目录与授权**

- **FR-001**: 系统 MUST 维护一份确定的工具目录，目录中每个工具 MUST 具备真实可用的执行能力；不具备执行能力的工具 MUST NOT 出现在可选目录中。
- **FR-002**: Agent 配置中勾选的工具集 MUST 决定该 Agent 执行时实际可用的工具集合；未勾选的工具 MUST NOT 被成功调用。
- **FR-003**: 当模型请求调用未授权工具时，系统 MUST 拒绝该调用、向模型返回可读的拒绝原因，并写入一条可查的越权调用记录（含工具名、运行标识、时间）。
- **FR-004**: Agent 未勾选任何工具时，运行时 MUST 不向模型暴露任何工具，且 MUST NOT 出现任何工具调用成功。
- **FR-005**: 工具从目录下线时，系统 MUST 从存量 Agent 的勾选集中移除该工具，且 MUST 保留历史运行的工具配置快照不被追溯修改。

**脚本执行**

- **FR-006**: Agent MUST 能在隔离执行环境中运行脚本，v1 MUST 支持 Python 与 shell 两种入口。
- **FR-007**: 每次脚本执行 MUST 运行在独立且一次性的隔离环境中；执行结束即销毁，不与其他执行共享文件系统、进程空间与临时目录。
- **FR-008**: 隔离环境 MUST NOT 能访问宿主机的文件系统、宿主机环境变量中的凭证、其他运行的工作目录，以及系统内部服务。
- **FR-009**: 每次执行 MUST 有可配置的时长上限；达到上限 MUST 被强制终止，该步骤标记失败并给出超时原因。
- **FR-010**: 每次执行 MUST 有可配置的 CPU、内存与磁盘配额；超限 MUST 只终止该次执行，不得导致执行引擎不可用或影响其他运行。
- **FR-011**: 系统 MUST 采集并回传标准输出、标准错误与退出码，供模型继续推理与用户查看。
- **FR-012**: 输出超过上限时 MUST 截断并保留尾部，同时在结果中标注"已截断"与原始长度。
- **FR-013**: 执行以非零退出码或强制终止结束时，系统 MUST 返回结构化失败信息（失败分类 + 退出码 + 错误摘要），MUST NOT 将其当作成功结果回填给模型。
- **FR-014**: 用户取消运行，或运行累计耗时超出其总时长预算时，正在执行的脚本 MUST 被立即终止并释放资源。

**产出制品**

- **FR-015**: 脚本在隔离环境内产出的文件 MUST 可被收集为运行制品，并在运行详情中下载。
- **FR-016**: 单次执行的产出 MUST 受文件数量、单文件大小与总量上限约束；超限 MUST 截断并明确提示。
- **FR-017**: 每个制品 MUST 记录来源（所属运行、所属执行、原始路径）、大小与内容校验信息；下载内容 MUST 与执行时写出的一致。
- **FR-018**: 制品下载 MUST 遵循资源归属校验，非归属用户 MUST NOT 下载。

**网络策略**

- **FR-019**: 隔离环境默认 MUST 禁止对外网络访问；被禁止时的失败 MUST 向调用方返回可读原因，使模型能区分"策略禁止"与"目标不可达"。
- **FR-020**: 管理员 MUST 能按域名白名单放行沙箱的对外访问；白名单之外的访问 MUST 仍被拒绝，且拒绝行为 MUST 可审计。

**可观测、计量与审计**

- **FR-021**: 每次脚本执行 MUST 记录开始/结束时间、耗时、语言、退出码、资源峰值与失败分类，并可在运行详情中查看。
- **FR-022**: 脚本执行的资源消耗 MUST 计入用户用量（次数、累计时长、并发占用），并受并发与时长上限约束；超限 MUST 排队或拒绝并给出可读提示。
- **FR-023**: 脚本执行、工具越权拒绝、网络策略拒绝、制品超限截断 MUST 写入审计日志（主体、Agent、运行、动作、结果）。
- **FR-024**: 隔离基础设施不可用时，系统 MUST 快速失败并给出可读原因，MUST NOT 无限重试，MUST NOT 返回伪造的成功输出。
- **FR-025**: 脚本执行与工具调用 MUST 复用既有运行状态机与实时日志通道呈现，MUST NOT 引入与既有流程并行的第二套执行视图。

## 范围边界（不含）

- **不含** 外部工具服务器（MCP）接入与第三方工具市场 —— 独立特性（003）。
- **不含** 用户自定义镜像、运行时安装依赖、GPU 执行 —— v1 只提供预置基础环境。
- **不含** 内核级隔离加固（安全模块策略、用户态内核等）—— 宪法已注明归 P3 专项加固。
- **不含** 多机沙箱调度与跨节点迁移 —— v1 在单机执行节点内做并发控制。
- **不含** 交互式会话（notebook 式跨多次调用保留状态）—— 每次执行独立、无状态。
- **不含** 用户自定义定时任务 —— 独立特性（004）。
- **不含** 沙箱内调用 LLM —— 工具能力仅限搜索、抓取、计算、脚本执行。

## Key Entities *(include if feature involves data)*

- **工具（Tool）**: 系统中一个可被 Agent 调用的能力单元，含标识、名称、说明、参数契约、是否启用、执行方式（内置能力或脚本沙箱）。
- **工具授权（ToolGrant）**: Agent 与其可用工具的关联，含归属 Agent、工具标识、授权时间；决定运行时可用工具集合。
- **工具调用记录（ToolInvocation）**: 一次工具调用的审计事实，含运行、步骤、工具、参数摘要、结果状态（成功/拒绝/失败）、拒绝原因、耗时。
- **沙箱执行（SandboxExecution）**: 一次脚本执行，含所属运行与步骤、语言、脚本摘要、时长上限与资源配额、实际耗时、资源峰值、退出码、失败分类、终止原因。
- **制品（Artifact）**: 执行产出的文件，含所属运行与执行、原始路径、文件名、大小、内容校验、存储位置（复用既有实体）。
- **出网规则（EgressRule）**: 沙箱对外访问的放行规则，含域名、生效范围、创建者、启用状态。
- **执行配额（ExecutionQuota）**: 用户在单位时间内的执行次数、累计时长与并发占用上限及其实际用量。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 一个只做输出/读写本地文件的简单脚本，从发起调用到结果回传给 Agent 不超过 5 秒。
- **SC-002**: 覆盖 10 类越权尝试（读宿主文件、读宿主凭证、访问内部服务、fork 炸弹、内存耗尽、写满磁盘、路径穿越、提权、残留后台进程、超长运行）的验证中，成功逃逸次数为 0。
- **SC-003**: 超时脚本在其时限到达后 3 秒内被终止，且资源被释放（无残留进程、磁盘占用归零）。
- **SC-004**: 20 个脚本并发执行时，系统其他接口的 P95 响应时间劣化不超过 20%，且无请求失败。
- **SC-005**: 越权工具调用 100% 被拒绝并留痕，静默放行次数为 0。
- **SC-006**: Agent 勾选的工具集与其运行时可成功调用的工具集 100% 一致（含"空集"情形）。
- **SC-007**: 产出文件下载内容与执行时写出的内容一致率 100%（校验值逐一比对）。
- **SC-008**: 失败的脚本执行中，100% 能在运行详情看到可读的失败分类（超时 / 资源超限 / 退出码非零 / 基础设施不可用 / 策略禁止），而非笼统的"未知错误"。

## Assumptions

- 沙箱默认策略为**禁止对外网络**；需要外网时由管理员按域名白名单放行。
- v1 支持的执行入口为 Python 3 与 shell；其他语言在后续迭代按需扩展。
- 单次执行默认限额：时长 120 秒（可配，上限 600 秒且不超过所属运行的剩余时长预算）、CPU 1 核、内存 512MB、可写磁盘 256MB。
- 单次执行产出上限：文件数 50 个、单文件 20MB、总量 50MB；标准输出保留尾部 1MB。
- 预置基础环境包含标准库与常用数据处理/绘图库；**不支持**运行时安装第三方依赖，缺依赖时返回可读提示而非静默失败。
- 工具目录 v1 定为：联网搜索、网页抓取、计算、执行 Python、执行 shell。「网页抓取」与「执行代码」在旧版本中曾以不同名称出现，本特性统一为一份目录，并对存量 Agent 做一次性的勾选集迁移（迁移后行为与界面对齐）。
- 存量数据的兼容策略：工具名变更按「旧名 → 新名」映射迁移；无法映射的勾选（历史上从未实现的能力）直接移除，并在迁移日志中记录受影响 Agent 数量。
- 并发上限按执行节点配置，超出的执行进入排队；排队超过一定时长仍无可用资源时拒绝并提示。
- 沙箱内**不**保留跨调用状态：每次执行从干净环境开始，需要跨步传递的数据由 Agent 显式写入产出文件。
- 依赖：需要可用的隔离执行设施；设施不可用时脚本类工具不可用，其余工具照常可用（对应 FR-024 的快速失败）。

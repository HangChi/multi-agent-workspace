# Feature Specification: 依赖图谱与自动启动（021）

**Status**: Implemented（2026-11-21）

**Input**: 用户 2026-11-21「A1–A6 逐个完成」中的 A5：依赖 DAG 深化
（拓扑排序 / 关键路径 / 自动级联启动）。009 当时只做「硬门禁 + 完成通知」。

## 问题陈述

009 的依赖只有「一条边一条边地看」：详情里列出前置、被挡住时给提示。但流水线
真正要回答的两个问题没有答案：

1. **这条活后面还挂着谁？** 改需求、取消、延期时，影响面靠人脑记；
2. **哪条链最长？** 一条链上五件活串着，另一条只有一件——先干哪个不言自明，
   但系统里看不出这个差别。

以及一个自动化诉求：**前置完成后自动启动后续**。现在必须有人盯着铃铛再手动拖。

## 设计

### 1. 图谱（只读）

`GET /requests/{id}/dependency-graph` 返回**下游子图**：

```json
{"root_id": "...", "nodes": [...], "edges": [...],
 "topo_order": ["..."], "critical_path": ["..."],
 "has_cycle": false, "truncated": false}
```

- **拓扑序**：Kahn 算法，前置在前。有环时返回已排序部分 + `has_cycle=true`
  （009 的加边已拒绝成环，这里是防御，不是正常路径）。
- **关键路径**：DAG 上最长链（**按跳数**，边权 1）。没有工期数据，跳数是唯一
  可算的近似；将来有实际耗时再换权重。
- **未完成前置数**：每个节点带 `unmet_count`（含子图之外的前置——
  「我被挡住」是全局事实，不该只看子图）。
- 节点上限 300，超出 `truncated=true`（前端提示「只显示前 N 条」）。

### 2. 自动启动（写入，默认关）

`requests.auto_start` + `requests.auto_agent_id`（迁移 0021）。前置**全部终态**时，
settle 钩子投一条 Celery 消息，任务独立事务里走 `assignment_service.assign`。

三道幂等校验（任一不满足就跳过）：
1. 需求还在、`auto_start` 仍开、`auto_agent_id` 仍设；
2. 前置仍全部终态（`is_blocked`）——防止「解锁后又加了新前置」；
3. `assign` 自己的状态机与配额门禁。

**为什么默认关**：自动启动会在无人确认的情况下花配额。开关是**逐需求**的，
不是全局的——一条流水线可以自动化，而看板其余部分保持手动。

## 权限

| 动作 | 谁可以 |
|---|---|
| 读图谱 | 需求 owner / assignee / 项目参与者（与详情一致） |
| 设 `auto_start` / `auto_agent_id` | 创建者或项目 owner（与「改项目归属」同档） |

理由：自动启动会真的花钱（配额记在需求创建者），这是**归属级**决策，不是
「谁经手谁决定」。

## 需求

- **FR-001** 图谱端点（下游子图 + 拓扑序 + 关键路径 + unmet_count + truncated）。
- **FR-002** 拓扑排序用 Kahn；有环时 `has_cycle=true` 且不返回关键路径。
- **FR-003** 关键路径按跳数；无下游时为空数组（不返回单节点）。
- **FR-004** 节点上限 300，可配置；超出截断并标记。
- **FR-005** `requests.auto_start`（默认 false）+ `auto_agent_id`（FK SET NULL）。
- **FR-006** 前置全部终态后投递 `auto_start_request` 任务；任务三道校验后分配。
- **FR-007** 设自动启动的权限=创建者或项目 owner，否则 403。
- **FR-008** `auto_agent_id` 必须是该需求创建者自己的 agent，否则 404。
- **FR-009** 前端详情弹层「下游链」区块：拓扑序列表 + 关键路径徽章 +
  自动启动开关（勾选后必须选 Agent 才能保存）。

## 成功标准

- SC-001 A←B←C 链：topo_order 与 critical_path 均为 [A,B,C]，B/C 各 1 个未完成前置。
- SC-002 分叉（A→B、A→C、B→D）时关键路径为 [A,B,D]。
- SC-003 成员（editor）改自动启动 403；陌生人读图谱 404。
- SC-004 前端能看到下游链，且「勾了自动启动没选 Agent」时保存禁用。

## 范围外（如实记录）

- **「自动启动真的跑起来」未做端到端验收**：那要求前置需求真的执行完成
  （LLM 调用 + worker + 成本），本轮只验到「配置正确 + 图谱正确 + 任务已注册」。
  手工验证步骤写在 `quickstart.md`。
- 不做甘特图 / 时间估算 / 自动重排期（需要工期数据）；
- 不做「批量启动所有可启动需求」（一次点一堆会瞬间打满配额，需专门的确认流）。

# Research：项目成员角色（019）

## R-01 为什么 010 说「不设 role」，019 又要加

010 的原话是：「成员身份即角色，owner 恒为 `projects.owner_id`，第三态没有使用数据；
存一个只有单值的列是给未来埋坑。」

这句话在**当时**是对的，它防的是「先建个空列，然后永远只有默认值」这种投机设计。
但它成立的前提是「所有成员权限完全一致」。

这个前提在 009/010 之后被现实打破了：需求依赖、项目共享上线后，出现了「跨团队
要看进度」「甲方要看、不能改」这类诉求。二元模型只能靠「不加成员」近似，代价是
**可见性也一并丢掉**——用户于是回到微信截图，信息出了系统。

所以 019 加列不是推翻 010，而是它的前提变了。**判断正确性有保质期**，spec 里
把这层因果关系写清，避免后人以为 010 当初判断错了。同时只加**两个**值：
010 反对的是「空列投机」，不是「有数据支撑的第三态」。

## R-02 为什么只做 editor / viewer，不做权限矩阵

矩阵（自定义角色、逐动作授权）的成本不在存储，在**判定点数量**：每个写操作都要
查一次「这个角色有没有这个动作的权限」，权限一旦可配置，就要处理「权限变更后
正在进行的操作怎么办」「两个角色冲突怎么办」。

A4（部门 + 分派权限矩阵）是另一个维度的诉求——「谁能把活派给谁」，那是**组织**
问题，不是**项目内**问题。两者混在一起会变成一个四不像的 ACL 系统。

019 的判据很简单：成员要么能写项目内的东西，要么不能。两个值足够覆盖全部已知
场景；真出现第三种（如「能改标题不能改成本」），再议。

## R-03 为什么 viewer 写操作回 403 而不是 404

016 立的分工：**非相关人** 404（不暴露存在性），**参与者缺动作权限** 403
（他知道存在，只是不被允许）。

viewer 是参与者（他能读到这个项目和这条需求），所以必须 403。回 404 会让他
以为自己被踢出项目了，去问 owner「你是不是把我删了」——比直接说「你只能看」
更糟。

## R-04 为什么在 `get_request` 上加 `require_write`，而不是给写端点单独判

写端点（PATCH / assign）本来都要先取需求做事，`get_request(allow_member=True)`
就是那道门。加一个布尔参数：

- 保持**一处判定**（归属 + 角色在同一个函数里，不会出现「某个端点忘了查角色」）；
- `require_write` 只在**成员快路**里生效：owner 与 assignee 走 `_check_owner`，
  不受影响（他们不是靠成员身份进来的）；
- 默认 `False`：所有既有调用方行为逐字节不变（零回归的关键，与 010 的
  `allow_member` 同一手法）。

## R-05 `member_role` 为什么单独认 owner

owner 不在 `project_members` 表里（010 R-01：双写要同步是纯冗余）。如果
`can_write_in_project` 只查成员行，**创建者自己会被判定为「不能写」**——
这是最容易犯也最难发现的错（owner 改自己的需求被 403）。

所以 `member_role` 先判 `projects.owner_id`，命中直接返回 `"owner"`，再查成员行。
这种「owner 不在成员表」带来的判定特例，010 里 `is_participant` 已经踩过一次，
这次的注释直接写明，避免第三次。

## R-06 为什么「转交责任」对 editor 仍是 403

007 的转交谓词是 owner-or-assignee，**不含项目成员**。019 没有动它：

1. 改了就是改 007 契约（「接收人才能转交」是那个特性的核心语义）；
2. 「我建的需求，别人替我转交给第三方」在责任链上是混乱的——要协作应该走
   「归属 + 分配执行」，而不是悄悄换责任人。

所以权限矩阵里 editor 的「转交」是 ❌，这不是漏做，是刻意保留。前端不需要提示
（拖到员工卡本来就只有 owner/接收人看得到入口）。

## R-07 前端为什么把角色做进列表行，而不是只在添加时选

角色是**持续状态**，不是一次性动作：用户需要随时看到「谁只能看」，否则半年后
没人记得当初为什么某人加不进东西。所以列表行直接给「只读 / 可编辑」徽章；
只读成员自己也会看到一句说明（否则他改不动会觉得是 bug）。

## R-08 迁移为什么零回填

`server_default='editor'` 让所有既有行自动获得「010 的行为」。没有 UPDATE 语句：
回填反而危险——如果哪天默认值语义变了，一次性 UPDATE 会把历史行和新行混在一起
且不可追溯。

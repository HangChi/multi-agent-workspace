# Feature Specification: 核心工作流（Core Workflow）

**Feature Branch**: `feat/core-workflow`

**Created**: 2026-11-14

**Status**: Draft

**Input**: User description: "Phase 1 核心闭环：用户认证与角色权限、Agent 与 Agent 组管理、需求创建与看板、拖拽分配、单 Agent LLM 执行、运行实时日志"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 注册登录与权限控制 (Priority: P1)

团队管理员通过邀请码创建团队，成员凭邀请码注册并登录。系统区分三角色：管理员（admin）可管理所有用户与全局配置；成员（member）可创建和管理自己的 Agent、组与需求；观察者（viewer）只能查看。用户登录后进入工作台，所有操作都受权限约束，未授权操作被拒绝并给出明确提示。

**Why this priority**: 认证与权限是系统的安全边界，所有后续功能都依赖「当前用户是谁、能做什么」。没有它，其他功能无法安全落地。

**Independent Test**: 可通过「注册新账号 → 登录 → 验证不同角色的可见范围与操作权限」独立验证，交付"安全的用户身份与权限体系"。

**Acceptance Scenarios**:

1. **Given** 用户未注册，**When** 使用有效邀请码注册，**Then** 注册成功并自动登录进入工作台
2. **Given** 已注册用户，**When** 使用正确凭证登录，**Then** 登录成功并获得会话凭证
3. **Given** 已登录的 viewer 角色用户，**When** 尝试创建 Agent，**Then** 操作被拒绝并提示无权限
4. **Given** 已登录的 member 角色用户，**When** 访问管理后台，**Then** 访问被拒绝并提示无权限

---

### User Story 2 - Agent 与 Agent 组管理 (Priority: P1)

成员可以创建 Agent（配置名称、描述、角色提示词、模型、温度、最大步数、可用工具集、成本上限），并编辑、归档、删除自己的 Agent。成员可以创建 Agent 组，把多个 Agent 加入组内并排序，为组选择默认路由策略（直接指定/并行分发/顺序管道/智能路由）。Agent 和组都遵循资源归属：用户只能管理自己的资源。

**Why this priority**: Agent 与组是任务执行的载体，是「拖拽分配」的目标对象，没有它们核心交互无法成立。

**Independent Test**: 可通过「创建 Agent → 创建组 → 组内增删排序 Agent → 配置路由策略」独立验证，交付"可配置的多角色执行单元"。

**Acceptance Scenarios**:

1. **Given** 已登录 member，**When** 创建一个含提示词、模型、工具集的 Agent，**Then** Agent 创建成功并出现在自己的 Agent 列表
2. **Given** 已存在 Agent，**When** 编辑其提示词与成本上限，**Then** 修改生效且历史运行不受影响
3. **Given** 已存在两个 Agent，**When** 创建组并将它们按顺序加入、选「顺序管道」策略，**Then** 组创建成功且成员顺序与策略被保存
4. **Given** 用户 A 的 Agent，**When** 用户 B 尝试编辑，**Then** 操作被拒绝并提示无权限

---

### User Story 3 - 需求创建与看板 (Priority: P1)

成员可以创建需求卡片（标题、描述、期望产出、优先级、附件），需求进入看板的「待分配」列。看板按状态分组展示需求（待分配/执行中/已完成/失败/已取消），支持按关键词搜索。成员可随时查看需求详情与附件。

**Why this priority**: 需求是任务的内容载体，看板是核心交互的起点，拖拽分配需要「可拖动的需求卡片」。

**Independent Test**: 可通过「创建需求 → 上传附件 → 看板按状态展示 → 搜索定位」独立验证，交付"需求管理与可视化看板"。

**Acceptance Scenarios**:

1. **Given** 已登录 member，**When** 填写标题、描述、优先级并提交，**Then** 需求创建成功并出现在看板「待分配」列
2. **Given** 需求已创建，**When** 用户上传附件，**Then** 附件保存成功并可在详情中下载
3. **Given** 看板有多个不同状态的需求，**When** 用户查看看板，**Then** 需求按状态正确分组展示
4. **Given** 看板存在多个需求，**When** 用户输入关键词搜索，**Then** 只展示标题或描述匹配的需求

---

### User Story 4 - 拖拽分配与任务入队 (Priority: P1)

用户把需求卡片拖到某个 Agent 或 Agent 组上。拖到单个 Agent 时直接生成一次执行；拖到组时弹出确认框选择路由策略（默认用组配置的策略）。确认后任务进入执行队列，需求卡片状态变为「执行中」。系统立即返回任务已受理，执行过程在后台推进。

**Why this priority**: 拖拽分配是产品的核心交互——「用户把需求拖到对应的 agent 或 agent 组中」，是需求与执行引擎的衔接点。

**Independent Test**: 可通过「把需求拖到 Agent → 确认 → 卡片状态变为执行中 → 队列出现任务」独立验证，交付"从需求到执行的分发闭环"。

**Acceptance Scenarios**:

1. **Given** 看板有待分配的需求和一个 Agent，**When** 用户把需求拖到该 Agent 并确认，**Then** 任务被受理，需求状态变为「执行中」
2. **Given** 看板有待分配的需求和一个组，**When** 用户把需求拖到该组并选择路由策略，**Then** 按所选策略生成执行，需求状态变为「执行中」
3. **Given** 需求已处于「执行中」，**When** 用户再次拖拽该需求，**Then** 系统拒绝并提示需求已在执行
4. **Given** 用户尝试把需求拖到已归档/无权限的 Agent，**When** 拖放，**Then** 系统拒绝并给出原因

---

### User Story 5 - 单 Agent 执行与实时反馈 (Priority: P1)

任务入队后，执行引擎驱动 Agent 完成需求：理解需求、调用可用工具（含联网搜索等）、生成最终产出。执行过程实时可见：用户打开运行详情页能看到状态流转（排队中/执行中/已完成/失败）与逐步执行日志（每一步的输入输出可展开查看），执行中的成本实时累计。执行完成后展示最终结果与产出制品，失败时给出可读的错误信息并可手动重试。

**Why this priority**: 执行引擎是系统的价值核心——「agent 会执行对应的任务」，实时反馈让用户信任并掌控执行过程。

**Independent Test**: 可通过「提交需求 → 观察执行过程实时日志 → 查看最终结果与制品 → 失败后重试」独立验证，交付"从执行到产出的完整闭环"。

**Acceptance Scenarios**:

1. **Given** 需求已分配并排队，**When** 用户打开运行详情页，**Then** 看到状态实时流转与逐步执行日志
2. **Given** Agent 执行完成，**When** 用户查看运行详情，**Then** 看到最终结果与产出制品（如有）
3. **Given** Agent 执行失败，**When** 用户查看运行详情，**Then** 看到可读的错误信息并可一键重试
4. **Given** 执行中的任务，**When** 用户点击取消，**Then** 任务停止并被标记为已取消
5. **Given** 需求执行中，**When** Agent 需要用户补充信息，**Then** 运行进入「等待补充」状态，用户可回复后继续

---

### Edge Cases

- 邀请码无效、过期或已被使用：注册被拒绝并提示原因。
- 重复邮箱注册：系统提示邮箱已被注册。
- 登录失败（密码错误/账号禁用）：提示凭证错误，不泄露账号存在性。
- 同一用户并发创建大量需求：系统正常受理，看板分页展示不卡顿。
- 任务执行超时（超过 Agent 配置的最大时长）：任务被标记失败，提示超时原因。
- LLM 服务不可用/限流：执行失败并给出可读错误，重试可恢复。
- 执行中途用户取消：已产生的步骤保留，任务标记已取消，不继续执行。
- 附件过大或类型不支持：上传被拒绝并提示限制。
- 删除/归档被其他组引用的 Agent：系统提示引用关系，禁止删除。
- 拖拽目标在拖拽过程中被归档/删除：分配失败并提示刷新后重试。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 支持用户通过邀请码注册账号（邮箱+密码）。
- **FR-002**: 系统 MUST 支持用户登录与登出，登录后获得会话凭证。
- **FR-003**: 系统 MUST 实施三角色权限：admin / member / viewer，所有资源操作遵循归属校验。
- **FR-004**: 系统 MUST 允许 member 创建、编辑、归档、删除自己的 Agent。
- **FR-005**: 系统 MUST 允许 member 配置 Agent 的角色提示词、模型、温度、最大步数、工具集、成本上限。
- **FR-006**: 系统 MUST 允许 member 创建、编辑、删除自己的 Agent 组。
- **FR-007**: 系统 MUST 允许 member 向组内增删 Agent 并排序，为组配置默认路由策略。
- **FR-008**: 系统 MUST 允许 member 创建需求（标题、描述、期望产出、优先级、附件）。
- **FR-009**: 系统 MUST 在看板上按状态分组展示需求，支持关键词搜索。
- **FR-010**: 系统 MUST 支持用户把需求拖到单个 Agent 或 Agent 组，触发任务分配。
- **FR-011**: 系统 MUST 在拖到组时提供路由策略选择，默认取组配置。
- **FR-012**: 系统 MUST 拒绝将已在执行的需求再次分配。
- **FR-013**: 系统 MUST 将分配后的任务入队，需求状态变为执行中。
- **FR-014**: 系统 MUST 驱动单 Agent 执行：理解需求、调用工具、产出最终结果。
- **FR-015**: 系统 MUST 实时推送运行状态流转与分步日志（排队中/执行中/已完成/失败/等待补充/已取消）。
- **FR-016**: 系统 MUST 在执行完成后展示最终结果与产出制品，支持下载。
- **FR-017**: 系统 MUST 在失败时提供可读错误信息，支持手动重试。
- **FR-018**: 系统 MUST 支持用户取消执行中的任务。
- **FR-019**: 系统 MUST 在执行中实时累计并展示成本，成本不超过 Agent 配置上限。
- **FR-020**: 系统 MUST 记录所有敏感操作的审计日志（登录、Agent/组变更、分配、取消、重试、凭证修改）。
- **FR-021**: 系统 MUST 在执行需要补充信息时进入「等待补充」状态，用户回复后继续。

### Key Entities *(include if feature involves data)*

- **用户（User）**: 注册账号，含邮箱、密码、角色、状态；与 Agent/组/需求/运行为一对多关系。
- **Agent**: 可执行任务的执行单元，含名称、描述、提示词、模型、温度、最大步数、工具集、成本上限、状态、归属用户。
- **Agent 组（AgentGroup）**: 用户的 Agent 集合，含名称、描述、默认路由策略、有序成员、归属用户。
- **需求（Request）**: 任务卡片，含标题、描述、期望产出、优先级、附件、状态、归属用户。
- **运行（Run）**: 一次具体执行，含所属需求、分配目标（Agent/组）、路由策略、状态机、当前步骤、结果、错误、成本、时间戳。
- **步骤（Step）**: 运行内的一次原子动作（LLM 调用/工具调用/结果回填），含输入、输出、耗时、成本、状态。
- **制品（Artifact）**: 运行/步骤产出的文件，含存储位置、文件名、大小、类型。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 新用户可在 2 分钟内完成注册并登录进入工作台。
- **SC-002**: 从拖拽需求到任务被受理（需求状态变为执行中）不超过 3 秒。
- **SC-003**: 用户在运行详情页看到的日志延迟不超过 2 秒。
- **SC-004**: 从需求拖拽到完成一次简单 Agent 执行（无外部依赖）不超过 5 分钟。
- **SC-005**: 无权限操作 100% 被拒绝并给出明确原因提示。
- **SC-006**: 执行成本始终不超过 Agent 配置上限，超限自动终止并提示。
- **SC-007**: 系统同时支撑 20+ 个需求执行而看板与详情页无明显卡顿。
- **SC-008**: 执行失败时用户可在一键重试后成功完成（重试成功率 ≥ 80%）。

## Assumptions

- 目标用户为团队内部成员，注册采用「管理员持有邀请码，成员凭码注册」模式。
- 邀请码由管理员在管理后台生成并发放，v1 不做自助申请。
- 密码采用加密存储；密码重置 v1 不做，由管理员协助处理。
- 附件单文件上限默认 20MB，支持常见文档/图片/压缩包类型。
- 默认提供至少一个内置工具（联网搜索），其余工具在后续特性扩展。
- 执行超时默认 30 分钟，可在 Agent 配置中调整。
- 组路由策略 v1 实现「直接指定」与「并行分发」，「顺序管道」与「智能路由」在后续特性落地（本特性保留策略字段与选择入口）。
- 需求看板 v1 不做复杂筛选与分组拖拽排序，仅按状态分组 + 关键词搜索。
- 依赖：需要可用的 LLM 服务（通过统一网关接入，具体模型可配置）。
